# 从 arXiv 到中文 Typst：一份手工做的 STEM 语料

这个仓库做的事很朴素：把 arXiv 上量子计算与芯片制造工艺方向的前沿论文，一篇一篇人工翻译成
中文 Typst 文档，示意图该重画的用 CeTZ 重画，编译成 PDF，然后把整个过程中攒下的脚本、
排版判断和踩过的坑全部留在仓库里。

为什么要费这个劲。中文世界里系统、准确、还愿意把公式和图讲清楚的 STEM 材料太少了，
而它恰恰是训练和评测科学推理最需要的东西。arXiv 上的预印本每天都在增加，绝大多数
从来没有人把它变成中文。与其等别人做，不如自己一篇篇啃下来，做完就放在这里，
谁都可以拿去用——做语料、做教材、做检索基准、做模型评测，都行。

我们相信开放的语料应该是所有人的基础设施。所以代码与译文用 MIT 授权，做完一篇就推一篇，
不藏进度，不设门槛。

## 里面有什么

`papers/<arxiv-id>/typst/` 是每篇论文的成品：`main.typ` 是译文正文，`supple.typ` 是补充材料
（有的话），`refs.bib` 是清洗过、只保留被正文引用条目的参考文献，`fig/` 里既有保留的原图，
也有用 CeTZ 重画的矢量框图，`main.pdf` 是编译结果。想读译文直接看 PDF；想知道我们怎么排的，
看 `.typ` 源码，注释里写了不少判断。

`tools/` 是排版体检脚本，十个左右，每个都对应一类真实踩过的坑：页内空白带、公式顶出右栏、
定界符不配平、参考文献里的 LaTeX 残留、编号公式错位。`tools/README.md` 讲每条怎么用。
这些脚本是从反复渲染—看图—修—再渲染的循环里长出来的，不是先设计后实现的。

`经验记录.md` 是这个仓库最有价值的部分。它按轮次记录每一篇的排版发现：Typst 0.15.1 里
`$...$` 内的 `\` 能把一条编号公式拆成视觉多行而只保留一个编号；`figure(float: true)` 这个参数
根本不存在，所以图块不可切分、放不下就必然留白；`lang: "zh"` 下 `@ref` 会把公式编号的 `S` 前缀
吃掉；`first-line-indent: 2em` 不缩进每节的第一段，必须写 `(amount: 2em, all: true)`。
八条这样的发现累积起来，比任何一份"Typst 中文排版教程"都管用。文件是多个协作方
追加写成的，只追加、不重写。

`community.md` 是协作看板：谁认领哪篇、当前状态、交付前必查的七项清单、新协作方上手要走的
三步。它同时是工作日志，每条交付记录都写清页数、告警数、以及为什么某些版面问题选择不修。

## 怎么重新编译

需要 Typst 0.15 以上，以及 Noto Serif SC 和 New Computer Modern 两套字体。

```
cd papers/2609.20775/typst
typst compile main.typ main.pdf
```

补充材料和正文在同一个 `main.typ` 里通过 `include` 串起来，所以一条命令出整篇。

体检脚本可以单独跑，比如在某个 `typst/` 目录下：

```
python ../../tools/blank_bands.py main.pdf _chk      # 量每页最大空白带
python ../../tools/margin_overflow.py main.pdf _chk  # 找压到页边距上的墨迹
python ../../tools/eq_map.py                         # 数出编号公式与总数
```

## 关于原图和原文

译文、排版源码、脚本、日志这些都是我们做的，MIT 授权，随便用。论文原文和其中的实验数据图
版权归原作者与出版方，我们从 arXiv 取源、只保留编译所需的最小素材，原始 `.tex` 与打包下载
不入库。这份译本的意义在于把内容用中文重新讲一遍、把版式重做一遍，属于研究性使用；
如果权利方认为需要下架某个文件，提出来我们就删，不用走复杂流程。
